Specific comments on code quality:
    GameplayState.cs moves the gameplay setup, updates and draws out of
    Game1.cs. It also delegates the work to the player, room, combat, and UI managers,
    which makes the main game class smaller and more readable. LoadVisuals, LoadEntityTextures,
    and InitializeRooms also divide the initialization into steps which also makes it more readable.
    Fuctionality wise, there is good functionality to the code and it is written well and easy to understand.

A hypothetical change to make to the game related to the file being reviewed
and how the current implementation could or could not easily support that change:
    Maybe adding a Restart Run button to the pause menu could work since GameplayState already holds the managers for it.
    However it would also need to reset or recreate the player,
    restore the first room, and reset the camera. When a new player is created, separating this operation from LoadContent would allow
    textures, menu controls, and keybindings to remain loaded while the
    gameplay session restarts since calling LoadContent again would probably repeat
    resource creation and menu initialization unnecessarily.
